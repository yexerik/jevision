How validation works

Jev checks the visible screenshot for clipped content, unintended overlap, and unreadable text. An example reference adds a comparison check.

Each percentage estimates the chance of a problem. Overlap is flagged at 60% or above; other checks at 70% or above. Above 30% needs review. Clipping and overlap can both be flagged.

These thresholds were assessed on synthetic layouts and reference controls. Review the screenshot yourself; a low score does not guarantee a correct page.

Rendering is offline. Inline CSS, scripts, and embedded images work; external resources and local files are blocked. Only the selected viewport is checked.

About this version
Understanding results
Model confidence

A confidence percentage is the model's signal about its answer. It is not measured accuracy on your photos.

Precision and recall

With reference labels, precision measures how many returned boxes were correct; recall measures how many real objects were found. IoU measures overlap between predicted and reference boxes. Benchmarks use .50 as the primary overlap requirement and .30 for looser localization.

Review states

V5 separates confirmed-by-checks results from located boxes needing extent review. Confirmed does not mean independently verified. Unresolved identity groups and cluster references are not extra objects. A completed minimum scan does not guarantee every object was found.

How boxes are accepted

Choice determines whether this crop has none, one, or several targets. A Box question runs alongside Choice.

Coordinate mapping

Each question points to a named crop. The red-outline check accepts a recognizable target clipped by a crop or partly hidden.

Low-confidence box check

Several crops split. Low-confidence boxes get a red-outline check; uncertain boxes split and search again.
